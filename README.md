# malecns-OSRS

A real fruit-fly connectome playing a 2004-era RuneScape emulator.

The MaleCNS v1.0 *Drosophila* brain — 184,110 neurons and 10.65 million signed synapses from
Janelia's EM reconstruction — runs as a spiking network on a laptop. A synthetic fly-eye retina
renders the game world into its optic lobe; its descending neurons are read out as walk, turn,
flee, attack. The game is [LostCity](https://github.com/LostCityRS/Server), an open-source
2004scape emulator, driven through [MaxBittker/rs-sdk](https://github.com/MaxBittker/rs-sdk).
No pixels, no keyboard: structured game state in, structured actions out, over a unix socket.

**Status: the loop is closed and measured; nothing here claims the fly plays well.** The fly
walks under network control, its behaviour changes when named neurons are lesioned, and a
degree-preserving shuffle of the wiring is run as a control every time it is scored. Whether the
connectome's *specific* wiring does anything beyond its degree sequence is the open question,
and the harness in `tools/ablation.py` exists to answer it either way. Read `runs/ablation.json`
and the report it prints, not this paragraph, for the current answer.

## Why this exists

[FlyBrain-HalfLife](https://github.com/Yusuftmle/FlyBrain-HalfLife) is the project that made
"a fly brain plays a video game" a thing, and its README cites MaleCNS v1.0. Reading its code
shows that the connectome it simulates is generated by modular arithmetic, the named cells are
array-index assignments, and steering is computed in NumPy and *injected into* the neurons it
then reads back out. The network could be deleted without changing behaviour. The claim is
unfalsifiable by construction.

This repo is an attempt to build the thing that README describes, with the measurement as the
deliverable:

- **The connectome is the real release.** Fetched with SHA-256 checksums, compiled with
  provenance, every named population resolved to body IDs you can paste into neuPrint.
- **Behaviour has to come through the network.** `motor/decode.py` takes firing rates and a
  population index and nothing else — its signature is asserted by a test, and an AST test
  forbids it importing game state. `sensory/` may never import `motor/`. That firewall is the
  project's central correctness claim.
- **It has to be able to come out negative.** The ablation harness runs a degree- and
  sign-preserving random rewire as a control. If the shuffle plays as well as the real wiring,
  the report says so in those words.

## How it works

```
MaleCNS feather (1 GB) ──build, offline──► connectome_v1.npz  (184,110 neurons, signed CSC)
                                                     │
┌──────────────────── Python: the fly ────────────────┼──────────────────────────┐
│  sensory/retina ─► sensory/encode ─► engine/lif (event-driven LIF)               │
│        ▲            [no action access]        │                                  │
│        │ WorldState                 descending-neuron rates                      │
│        │                                      ▼                                  │
│        │                     motor/decode [no state access] ─► motor/body        │
└────────┼──────────────────────────────────────────────────────────┼─────────────┘
         │ NDJSON over /tmp/malecns-osrs/<bot>.sock                   │
┌────────┴──────────── Bun: bridge/sidecar.ts (rs-sdk BotSDK) ───────▼─────────────┐
│  state ─► conflate (depth 1) ─► push · cmd ─► verified sdk.send* · deadline      │
└──────────────────────────────────┬──────────────────────────────────────────────┘
                                   │ ws://localhost:7780
                   game client (lite or headless Chromium) ──► LostCity engine
```

- **Engine.** Current-based leaky integrate-and-fire, exponential Euler, delay ring buffer,
  spike-frequency adaptation. Synaptic input is an event-driven gather over the CSC columns of
  the neurons that fired, so cost is *edges touched per step*, not matrix size. numpy + scipy
  are the whole hot path; there is no PyTorch and no GPU, deliberately — 6,000 tiny kernel
  launches per tick would be slower than the gather.
- **Retina.** A 60×60 top-down egocentric raster, four sub-frames per game tick so the optic
  lobe's own motion detectors (T4/T5, via L1/L2/L3/Tm1) see real optic flow. It is a
  *metaphor*: a fly's eye is forward-facing and hexagonal, this is a bird's-eye tile map. The
  flow is genuine; it is not fly flow.
- **Readout.** DNa02 left/right → turn; a pooled descending-neuron family → drive; DNp01 (the
  Giant Fiber) → escape on a burst above its own baseline; attack/eat/pickup pools → the act,
  resolved by `motor/body.py` to *whatever lies in the fovea*. The brain is never handed "the
  nearest chicken".
- **Reward.** Damage dealt / kills / XP → PAM dopaminergic neurons; damage taken / death → PPL1.
  KC→MBON synapses are plastic, gated by DAN rate with eligibility traces (`--learn`). The
  learning signal is a network variable, not a game number.
- **Bridge.** One state per tick, conflated to depth 1 so the brain is never quietly behind
  reality. A per-tick deadline (0.85 of the tick); overruns fall back to a continuation policy
  and are counted. Dispatch is verified against the next state, because rs-sdk's `send*` reports
  only that bytes were written.

## Quick start

Requires Python ≥ 3.14 with [uv](https://docs.astral.sh/uv/), [Bun](https://bun.sh), and
~2 GB of disk for the connectome release. Developed on macOS arm64; nothing is platform-bound.

```bash
git submodule update --init --depth 1        # pinned rs-sdk
uv sync
bun install                                  # typecheck tooling for bridge/
(cd vendor/rs-sdk && bun install --frozen-lockfile && cd server/webclient && bun install --frozen-lockfile)

uv run python -m tools.fetch_connectome      # MaleCNS v1.0, resumable, SHA-256 verified
uv run python -m flybrain.connectome.build --out data/cache/connectome_v1.npz
uv run python -m tools.build_collision       # Lumbridge collision grid for the retina
uv run python -m flybrain.engine.calibrate --drive encoder --save data/cache/calibration_v1.json
```

Then bring the game up and let the fly loose:

```bash
uv run python -m flybrain.app up --tickrate 176 --client browser --no-wait
uv run python -m flybrain.loop.run --hud
uv run python -m flybrain.app down
```

`flybrain.app` supervises the whole stack — LostCity engine, rs-sdk gateway, a game client, and
the bridge sidecar — in its own process groups, so `down` takes everything with it.
`--client lite` is headless and cheap; `--client browser` runs a headless Chromium so the HUD's
game panel is live. The first `up` builds the web client bundle and creates a bot account with
a local-only `bot.env` (`TELEMETRY=false`, pointed at `localhost` — never the public server).

`--hud` opens a telemetry window: the game feed, the real 3D soma cloud lit by each neuron's
departure from its own baseline, the retina the brain actually saw, a population raster, the
descending-neuron readout beside the command it became and the action that was sent, and
ms-per-tick against the deadline. `q` closes it; the brain keeps running.

## Calibration

The raw connectome is bistable under a scalar gain: silent or avalanching, with a cliff of three
orders of magnitude over a 0.06 % change in gain. What holds it in band, in order of how much
each mattered: driving the search with the **real encoder output** rather than a synthetic
amplitude; per-neuron incoming-weight normalisation; a just-subthreshold tonic drive;
spike-frequency adaptation; and an acceptance predicate on the *distribution* (silent fraction,
saturated fraction, bimodality, median > 0), not the mean. The accepted network must also beat
a connectome-free null by 1.5×, or the wiring is doing nothing the tonic drive isn't.

Calibrated 2026-09-15 at `dt = 2 ms`: mean 4.57 Hz, median 3.0 Hz, 0.5 % silent, 2.2× null.
The artifact carries every parameter, the git revision, and a fingerprint of the connectome it
was measured on; a stale one is fatal, not a warning. The motor decoder's thresholds are
multiples of the measured rate, read from the same artifact, so the two cannot drift apart.

## Falsifiability

```bash
uv run python -m tools.ablation --episodes 10 --ticks 200 --substeps 19 --hud --out runs/ablation.json
```

Six conditions, N episodes each, scored on the live game with bootstrap confidence intervals and
Hedges' *g*:

| condition | what it removes | expectation if the wiring works |
|---|---|---|
| `real` | nothing | baseline |
| `lesion:DNp01` | the Giant Fiber | flee disappears, foraging intact |
| `lesion:DNa02` | the steering neuron | steering undirected, attack survives |
| `lesion:optic` | 14 optic-lobe types | wandering undirected |
| `ablate-network` | every synapse | collapse to the tonic floor |
| **`shuffle`** | the specific wiring, keeping every neuron's degrees and transmitter sign | **must degrade** |

The report states each expectation and whether it held, prints the shuffle verdict in one of
four fixed sentences, and derives its caveats from the run's own measurements — per-condition
overrun, ms per tick, the observed tick — rather than quoting an earlier run. It refuses to
print a verdict at all when the primary metric had no variance, because that is how the first
scored run produced a confident sentence off a column that was zero everywhere.

Measured floor for a valid run: 19 LIF substeps per retina sub-frame (152 ms of simulated time
per tick — below that the decoded drive collapses and the bot stops moving) and a game tick of
at least ~145 ms so the hottest condition clears its deadline. `NODE_TICKRATE=176` is the
setting used; a 600 ms tick is real OSRS speed and takes 3.4× longer per episode.

## Verification

```bash
uv run pytest
uv run ruff check .
uv run ruff format --check .
bunx tsc --noEmit
```

Run from the repo root. Among the tests: the decoder's two-parameter signature and its import
allowlist; Dale's law per presynaptic neuron on the compiled artifact; Giant Fiber in/out
degree as an orientation check on the weight matrix (it once ran backwards and every
self-consistency test passed); the calibrated live path using the artifact's values rather than
defaults; and plasticity moving *both* the weights and the network's response to a fixed input.

## Layout

- `flybrain/` — the package. `engine/` spiking simulation and calibration, `connectome/` fetch,
  select, compile, registry; `sensory/` and `motor/` the two halves of the loop; `loop/` the
  tick driver and bridge client; `hud.py` telemetry.
- `bridge/` — the only TypeScript: the Bun sidecar owning the rs-sdk connection, and the game
  screencast feed.
- `tools/` — offline scripts: data fetch, collision build, the ablation harness.
- `vendor/rs-sdk` — pinned submodule, never edited.
- `data/` — gitignored; checksums are committed, the release is not.
- `docs/`, `AGENTS.md` — how work is done in this repo, including the delegation rules.

## Scope and ethics

This targets **LostCity only**, an open-source 2004scape emulator explicitly not endorsed by
Jagex. It must never be pointed at live Old School RuneScape: automating a bot there violates
Jagex's terms and is bannable. The bot account is local, and rs-sdk's telemetry is switched off
so no bug reports leave your machine.
